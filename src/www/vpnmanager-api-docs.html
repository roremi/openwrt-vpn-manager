VPN Manager API Documentation

Unified API for profile lifecycle, device VPN assignment, policy routing, WiFi binding, MultiEbay import, and transactional apply/rollback.

Base Path: /cgi-bin/luci/admin/services/vpnmanager Write APIs use POST form fields Read APIs use GET
Authentication follows LuCI session rules. Call these endpoints from a logged-in browser session, or include the proper LuCI auth context in automation.
Software mode (no LuCI login): use token-protected endpoints under /cgi-bin/luci/vpnmanager/api/v1 with header X-API-Key.

Core Read APIs

MethodPathPurpose
GET/profilesList VPN profiles with status and handshake age.
GET/devicesList LAN devices from DHCP and ARP, including online state.
GET/policiesList per-device routing policies.
GET/statusDashboard counters: healthy/down profiles.
GET/route_statusRoute target and egress IP summary (cached for performance).
GET/auditLatest audit log lines.
GET/wifiCurrent WiFi base settings.
GET/wifi_bindingsDedicated WiFi-over-VPN bindings.
GET/multiebay_settingsSaved MultiEbay settings (API key redacted status).

Quick Workflow: Assign VPN To A Device

This is the most common full-feature use case: import profile, bind device policy, verify route, then apply.

# 1) Import a WireGuard profile by raw config content
curl -s -X POST "http://192.168.1.1/cgi-bin/luci/admin/services/vpnmanager/import" \
  --data-urlencode "id=vpn_sg_01" \
  --data-urlencode "content=[Interface]
PrivateKey=...
Address=10.0.0.2/32
DNS=1.1.1.1
[Peer]
PublicKey=...
AllowedIPs=0.0.0.0/0,::/0
Endpoint=1.2.3.4:51820"

# 2) Assign one device to that VPN profile
curl -s -X POST "http://192.168.1.1/cgi-bin/luci/admin/services/vpnmanager/policy" \
  --data-urlencode "section=policy_sm_s911b" \
  --data-urlencode "hostname=SM-S911B" \
  --data-urlencode "mac=1e:95:1c:4d:d5:ac" \
  --data-urlencode "ip=192.168.1.195" \
  --data-urlencode "target=vpn_sg_01"

# 3) Validate route status and profile health
curl -s "http://192.168.1.1/cgi-bin/luci/admin/services/vpnmanager/route_status"
curl -s -X POST "http://192.168.1.1/cgi-bin/luci/admin/services/vpnmanager/test" \
  --data-urlencode "id=vpn_sg_01"

# 4) Apply staged changes atomically
curl -s -X POST "http://192.168.1.1/cgi-bin/luci/admin/services/vpnmanager/apply"
Best practice: use stable policy section ids and keep MAC + IP together. The backend deduplicates policy conflicts by MAC/IP automatically.

Error Model

PatternMeaningAction
{"ok":false,"error":"missing args"}Required form fields are missingValidate required request fields client side before submit
{"ok":false,"error":"profile not found"}Target profile id does not existRefresh profiles and retry with a valid id
{"ok":false,"error":"apply failed"}Reconcile stage failedCheck audit log, fix config, or call rollback
{"error":"unsupported method"}Wrong endpoint mapping to rpcd actionUse exact path listed in docs

Detailed Endpoint Examples

Request and response samples below use real payload shape from current LuCI controller and rpcd backend.

Software API without LuCI session

# Configure key once on router
uci -q set vpn-manager.global=vpn-manager
uci set vpn-manager.global.software_api_key='YOUR_STRONG_KEY'
uci commit vpn-manager
/etc/init.d/rpcd restart
/etc/init.d/uhttpd restart

# Read devices
curl -s -H "Authorization: Bearer YOUR_STRONG_KEY" \
    "http://192.168.1.1/cgi-bin/luci/vpnmanager/api/v1/devices"

# If custom header is stripped by HTTP stack, use query fallback
curl -s "http://192.168.1.1/cgi-bin/luci/vpnmanager/api/v1/devices?api_key=YOUR_STRONG_KEY"

# Set policy (device -> VPN profile)
curl -s -X POST -H "Authorization: Bearer YOUR_STRONG_KEY" \
    "http://192.168.1.1/cgi-bin/luci/vpnmanager/api/v1/policy" \
    --data-urlencode "section=policy_sm_s911b" \
    --data-urlencode "hostname=SM-S911B" \
    --data-urlencode "mac=1e:95:1c:4d:d5:ac" \
    --data-urlencode "ip=192.168.1.195" \
    --data-urlencode "target=vpn_sg_01"
{
    "ok": false,
    "error": "invalid api key"
}
